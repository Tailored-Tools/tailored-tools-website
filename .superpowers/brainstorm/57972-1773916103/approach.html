Site Architecture, Two Approaches

How to restructure tailored-tools.com from AO-only to portfolio consultancy

A

Clean Break, New Homepage, AO Becomes a Section

Recommended. New index.html as welcome page. Current AO content moves to /ao/ subdirectory. Each section gets its own page.

Structure:
/ → Welcome homepage (new)
/projects/ → PI + SS case studies
/ao/ → Current AO content (quiz, score, services, pricing)
/ao/blog/ → Existing 11 blog posts
/ao/methodology → Existing methodology page
/workshops/ → Community, meetups, ambassador
/about/ → James's journey, credentials
/links → QR linktree page
Pros: Clean URLs, each page is focused, AO blog/methodology URLs change but can redirect. Professional feel.
Cons: More files to maintain. Existing AO URLs (tailored-tools.com/#free-score) break without redirects.
B

Overlay, New Homepage, AO Stays at Root

New welcome index.html replaces current homepage. Current AO page becomes ao.html at root level. Blog stays at /blog/.

Structure:
/ → Welcome homepage (new)
/projects → PI + SS case studies
/ao → Current AO content (single page, as-is)
/blog/ → Existing 11 blog posts (unchanged)
/methodology → Existing methodology (unchanged)
/workshops → Community, meetups, ambassador
/about → James's journey, credentials
/links → QR linktree page
Pros: Simpler migration. Blog URLs don't change. Less restructuring.
Cons: Flat structure gets messy as content grows. AO content isn't grouped under its own path.

Shared Across Both

  • Shared nav bar across all pages: Home | Projects | AO | Workshops | About
  • Shared footer with contact, socials, privacy link
  • Existing design system, same colours, fonts, responsive approach
  • QR /links page is standalone (no nav, linktree-style)
  • james.jpg already exists in the repo, reused on homepage and about
  • GitHub Pages deployment stays the same
